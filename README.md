# thesis-voice

> 中文工科毕业论文的写法与批注改写。基于 41 篇真实中文学位论文与期刊论文的**实测文风指纹**，不是泛泛的写作建议。

`thesis-voice` 是一个 Agent Skill（Claude Code / DSH / 兼容 Agent Skills 格式的运行时都能装）。它做三件事：

1. **把导师批注翻译成动作**——"文字太多""这是 AI 角度""这里要想清楚"到底改什么。
2. **判断距离**——这段现在在「会被打回 / 合格 / 优秀」哪一档，差的是哪一项。
3. **给出能落地的句子**——不是"建议更具体"，而是把原句改到可对照的状态。

## 为什么可信：阈值是量出来的

把 41 篇拆成三套基准（6 篇学位论文整本 OCR + 13 篇期刊正文 + 19 篇摘要），算出 11 项指标。核心三条：

| 指标 | 学位论文正文（n=6） | 期刊正文（n=13） | 一份典型 AI 腔草稿 |
| --- | --- | --- | --- |
| 平均句长 | **52.8**（48.7–56.1） | 64.0 | 30.3 |
| >50 字长句占比 | **40.6%** | 52.2% | 8.7% |
| 相邻句长差 | **30.4** | 49.2 | 14.8 |
| 句长变异 CV | **0.70** | 0.80 | 0.45 |
| 数字/千字（纯正文） | **40.8** | 26.5 | 0 |
| "本文"/千字 | 1.0 | 0.8 | 0 |
| 硬空词/千字 | 0.4 | 0.6 | 0.0 |

**最后一行是关键**：真论文和 AI 腔草稿的空词密度可以一样低。所以"空话"不是删几个词能解决的——问题在句子长短、责任主体和证据。

同一批语料还量出了几条反直觉的剂量，用来否掉一些流行的"去 AI 味"建议：

- **破折号**：0.02/千字。工科论文几乎不用，不是"节奏工具"。
- **冒号**：4.6–5.1/千字。是主流写法，不是 AI 腔，**不要**改成破折号。
- **首先/其次/最后**：1.2/千字。是工科结构词，只打破等长，**不要**拆掉。
- **笔者 / 我们认为**：0 次。工科论文不用第一人称。
- **综上 / 由此可见 / 不难发现**：0.03/千字。基本不写。
- **值得注意的是 / 需要指出的是**：0.00–0.01/千字。

## 用法

### 1. 体检一段草稿

```bash
python3 scripts/voice_check.py 章节.md                  # 学位论文正文
python3 scripts/voice_check.py 摘要.md --target abstract
python3 scripts/voice_check.py 期刊稿.md --target journal
```

输出六块：指标对照（11 项）、偏离项与改法、无数字的结果句、空词与空话、句法重复、段级剂量与禁用项。

样本示例（对一份 781 字的真实草稿）：

```
== 文风体检（body）  正文 781 字 / 24 句 ==
【1】指标对照
  !! 平均句长         30.3   参考 45–85
  !! 长句占比          8.7   参考 30–70
  !! 句长CV         0.45   参考 0.55–1.2
  !! 相邻句长差        18.0   参考 24–80
  !! 本文密度          0.0   参考 0.2–4.5
【6】段级剂量与禁用项（工科版硬上限）
  段级超限 1 段（上限：AI 高频词每段 ≤2，三元并列每段 ≤2）
    第19段：三元并列 3 处
```

### 2. 处理导师批注

把批注原话贴给 Agent，让它按 `references/04-批注类型学.md` 归类：删冗余 / 补逻辑环 / 兑现标题 / 明确小节目 / 语气角度 / 精简表达 / 语句不通 / 格式细节 / 加分项。每条给「字面意思 → 真实要求 → 三档差距 → 改法」。

### 3. 从零写一节

按 `references/02-章节骨架.md` 的段落配方，先写章首承诺，再写每节论点，配证据，最后才落句子。写完跑体检。

## 渐进式加载：不要一次读完

| 层 | 内容 | 什么时候读 |
| --- | --- | --- |
| L0 | `SKILL.md` | 总是加载：三条硬判据、改写优先级、三档水平 |
| L1 | `references/` 里**一份** | 按任务挑：批注→04、写章→02、句子→03、去 AI 味→05、清病灶→06、交付→07、docx→08、差距→01 |
| L2 | `format/` 或 `workflow/` 的一份 | 仅当任务涉及版式或交付 |
| L3 | `legacy/`、`docs/`、脚本源码 | 只在追溯来源或排查脚本时读 |

**一个任务通常只需要 L0 + 一份 L1。** 要同时读两份以上，先想想是不是任务没拆开。

## 首次激活：把模板和流程熔进来

skill 自带的是方法和空壳。老师给的模板、流程、提交规矩，第一次用时由使用者注入：

1. **索取**：模板（docx/pdf）、流程或时间表、提交规矩（邮箱/命名/系统）。缺哪样问哪样。
2. **解析**：逐项填进 `format/本地格式规格.md` 和 `workflow/本地交付规格.md`，每项标依据，核不准的写"待确认"。**不要用常识补空。**
3. **验证**：随机挑三项反问答，确认符合预期，再把首行版本改成当天日期。

两份模板第 1 行现在都是 `# 版本：未填写`。没填之前，Agent 遇到版式或交付问题应当反问，而不是给默认值。

## 两层本地化：版式与交付

skill 只放**方法**，不放**你学校的事实**。两类事实各自一个目录，都是空模板：

| 目录 | 放什么 | 谁填 |
| --- | --- | --- |
| `format/` | 字体、字号、行距、题注、著录格式 | 使用者给模板，Agent 解析填入 |
| `workflow/` | 收件邮箱、文件命名、模板版本、截止日期、渠道禁忌 | 同上 |

两份模板的第 1 行都是 `# 版本：未填写`。**未填写时 Agent 不应给默认值**，而应反问。

公开仓库里这两份永远是空壳；你本机安装的那两份填了真实值，`git pull` 覆盖前先备份。

## 版式：不写死，由使用者注入

字体、字号、行距、页边距、图题位置、参考文献著录格式——各校各模板不同，本 skill **一个都不预设**。

第一次用：

1. 把学校模板（docx / 规范 PDF）或口头要求交给 Agent；
2. Agent 解析后逐项填进 `format/本地格式规格.md`，标注依据；
3. 之后每次写稿、改稿、自检都以这份为准。

`format/本地格式规格.md` 默认是空模板（第 1 行 `# 版本：未填写`）。**未填写时，Agent 不应凭经验给默认值**，而应向使用者索取。理由见 `format/README.md`。

## 它**不**做什么

- **不承诺降低 AIGC 检测率**。那是另一个目标函数，和"写出合格论文"不总一致。检测率不降但论文合格可以接受；反过来不行。
- **不插入错别字、口语词、故意的不通顺**来制造"人味"。这是应付检测，不是提高质量。
- **不建议"笔者认为""出乎意料的是"**。6 篇学位论文里这类表达合计 0 次，导师会判为"多余"。
- **不替代内容判断**。体检器只管文风：数据造假、逻辑错误的稿子也能通过。
- **不规定字体字号**。版式属于本地模板，写死在通用 skill 里只会带偏别人。

## 语料与方法

- 中文：28 篇（15 篇学位论文 + 13 篇期刊），2024–2026
- 外文：13 篇（RAG / GraphRAG / Self-RAG / RAPTOR / HippoRAG / MinerU / ALCE 等）
- 6 篇学位论文做了整本 OCR（3.7 万–5.4 万汉字/篇），其余取正文或摘要段
- 导师 17 条真实批注，用于批注类型学
- 全部指标可复现：`tools/` 里三个脚本

### 与 humanizer-zh-academic 的关系

`references/06` 逐条验过 [humanizer-zh-academic](https://github.com/redbaronyyyyy-eng/humanizer-zh-academic) 的 16 个 AI 模式。结论：**8 条直接采纳、5 条改造后用、3 条不能用于工科论文**（原因见文件）。那份 skill 的语料是社科/人文论文，目标是降低检测率；本 skill 的目标是让工科论文像合格的工科论文。
