# 09 对齐：挖坑—填坑的计数纪律

一份稿子被导师大改，八成不是句子不好，是**结构对不上**：摘要说三个问题，正文只解决两个；绪论承诺四项工作，目录只找到三项。读者（导师、评阅人）第一遍就卡在这种错位上。

这一份给一个可数、可查的做法。

> 方法论参考了闵帆《论文写作》系列中"挖坑—填坑一一对应"的思路，按中文工科毕业设计的语境重写；英文期刊的句数与字数规格不适用于中文，见文末「不要照搬」。

## 核心：一张对照表，四层咬合

```
摘要     ：问题 → 已有工作不足（挖坑，数出来几个）
绪论     ：每个坑一段（把坑讲清楚）
正文     ：每个坑一个小节（填坑）
测试     ：每个坑一条验证（坑填住了没有）
```

**坑的数量在这四处必须相同。** 写作顺序是：先定摘要的坑数 → 再让后面三处向它对齐。

### 对照表长这样（写作前先填）

| 坑 | 具体不足（一句话） | 填坑小节 | 验证用例/实验 | 证据（数字/对比） |
| --- | --- | --- | --- | --- |
| P1 | | 4.2 | T-CITE-01 | |
| P2 | | 4.3 | T-CONF-01 | |
| P3 | | 4.4 | T-QA-03 | |

填不满的行，就是你要么补工作、要么删坑的地方。**空着的行不允许留在稿子里。**

### 对不齐怎么办

三种情况，三种处理：

| 情况 | 表现 | 处理 |
| --- | --- | --- |
| 坑多活少 | 挖了 4 个坑，只做了 3 件事 | **删坑**（首选），或把两坑合并成一坑，并在正文说明"这两个不足同源" |
| 活多坑少 | 做了 4 件事，摘要只说 3 个坑 | 检查第 4 件事是否服务某个坑；服务不上就移到"工程实现"里，不占创新点 |
| 一对多 / 多对多 | 一个坑需要两项技术 | **在正文里明说对应关系**："P1 由 4.2 的解析与 4.3 的引用校验共同解决" |

最忌讳的是让读者自己去数。**对应关系要么天然成立，要么用一句话讲明。**

## 摘要：八到十句的配方

中文摘要按本地模板定长度（本科常见 400–1000 字；模板要求 400 字就别写 900），但**功能位不变：8–10 个，每个位置只干一件事**。字数变了只是每句长短不同，位置不能少。

| 位 | 功能 | 建议字数（按 400 字计） | 常见错法 |
| --- | --- | --- | --- |
| 1 | 场景与问题（谁、在什么情况下、卡在哪） | 40–60 | 写成"随着…的快速发展" |
| 2 | 已有做法 | 30–50 | 罗列技术名词，没有一个机制 |
| 3 | **不足（挖坑）** | 50–80 | 只说"效果不好"，不说在什么条件下因什么机制失效 |
| 4 | 本文做什么（总述） | 40–60 | 与第 3 句不对应 |
| 5–7 | 每项工作一句（填坑） | 每句 40–60 | 与第 3 句的坑数不一致 |
| 8 | 怎么验证 | 30–50 | "实验表明"却不给数据集/规模 |
| 9 | 结果 | 40–70 | 没有数字、没有基线 |
| 10 | 意义/边界（可选） | 30–50 | "具有重要意义""前景广阔" |

**硬规则**

1. 第 3 句挖几个坑，第 5–7 句就必须有几项工作。**数一遍。**
2. 第 9 句必须有数字；没有测量就写"完成了……并在……上验证"，不编百分比。
3. 摘要不出现"如图 1""第 3 章""未来展望"。
4. 摘要最后写。先把正文写定，再回来把摘要压成这十句——反过来会逼你为了凑句子而改结构。

## 绪论：摘要每句扩成一段

绪论的顺序与摘要**完全一致**，只是每句扩成一段：

| 摘要 | 绪论对应 |
| --- | --- |
| 第 1 句（场景问题） | 1.1 第一段：场景白描 |
| 第 2、3 句（已有工作与不足） | 1.2 研究现状：按方向分组，每组末尾落到不足 |
| 第 4 句（本文做什么） | 1.3 本文工作：编号列，每条对应一个坑 |
| 第 5–7 句（各项工作） | 1.3 每条各展开两三句 |
| 第 8–9 句（验证与结果） | 1.4 或第 7 章：怎么测、测出了什么 |

**自查法**：把摘要十句和绪论各级标题并排放，能一一对上就通过。

段落内部：每段 5–10 句，首句是断言式主题句，其余句子支撑它。读完绪论，读者应该已经知道全文 80% 的结构。

## 正文：一个坑一个小节

- 每个坑一个小节，小节标题里带这个坑的关键词。
- 小节开头用一句话说明"这一节解决 P几"。
- 小节结尾给一个可验证的结论（"该机制使……从 X 降到 Y"或"在 T-XX-01 中使用例通过"）。
- 不要在一个小节里解决两个坑，也不要跨小节填一个坑（除非已在对照表里声明）。

## 测试：逐坑验证

- 有几个坑就有几条验证，**一条不能少**。
- 每条验证写清：输入规模、对照基线、指标、数值、结论。
- 填不动的坑（比如时间来不及）要在"展望"里明确写"未验证"，不要装作验证过。

## 分层自查：五级过一遍

| 层级 | 查什么 |
| --- | --- |
| 章 | 章首承诺的几件事，章内是否逐条兑现 |
| 节 | 每节是否有明确目的（证明 / 对比 / 发现不足 / 定义）；答不上的节删掉 |
| 段 | 首句是否可被反驳；末句是收束还是空转 |
| 句 | 长短是否交替；是否装下了"条件+机制+结果" |
| 词 | 术语全文一致；缩写首次给全称 |

## 不要照搬英文期刊的规格

| 英文期刊做法 | 中文毕设为什么不适用 |
| --- | --- |
| 句子不超过 20 词 | 中文长句 50–90 字是常态，压到 20 词会让论证碎成清单（实测：学位论文均句 52.8 字） |
| 摘要正好 10 句、每句 ≤20 词 | 中文按功能位分 8–10 句即可，字数按 400 字控 |
| 12–20 个数据集、4–8 个对比算法、含近三年方法 | 本科毕设做不到。降到：2–3 个数据集/语料，1–2 个基线，基线要具名且可复现 |
| 消融实验逐技术验证 | 本科毕设至少给"整体 vs 基线"；能拆一项消融就加分 |
| LaTeX 引号与符号规范 | 我们出 Word，改查"中文引号字体、全半角、单位空格" |
