# 08 docx 修订与批注落地

导师返稿怎么落到 Word 里，才不会被打回、不会让 Word 报"文档损坏"。

**这份只讲机制。** 用哪个脚本、脚本在哪、模板是哪一版，看 `workflow/本地交付规格.md`。

## 三条铁律

1. **批注不能删。** 每条批注下面写回复。老师靠批注定位"你改了哪、怎么回的"。
2. **改动走修订模式。** 新增内容包在 `w:ins`，删除内容包在 `w:del`，**不要在删除位置用 `w:t`**。
3. **旧版本不覆盖。** 另存新版本，文件名带版本/日期/轮次。

## 关键 XML

| 元素 / 属性 | 作用 | 常见错法 |
| --- | --- | --- |
| `<w:ins w:id=".." w:author=".." w:date="..">` | 新增文字/段落 | 只加颜色没加 `w:ins`，老师看不到修订 |
| `<w:del>` | 删除容器 | —— |
| `<w:delText>` | **删除的文本必须用它** | 用 `w:t` 会导致 Word 打不开或提示损坏 |
| `<w:commentRangeStart w:id="N">` / `<w:commentRangeEnd w:id="N">` | 批注锚点的起止 | 只留 start 不留 end，锚点错位 |
| `<w:commentReference w:id="N">` | 引用批注 | 与 `comments.xml` 里的 id 不一致 |
| `word/comments.xml` | 批注正文 | id 重复或与正文引用不匹配 → "文档损坏" |

`w:id` 在正文与 `comments.xml` 之间必须**一一对应且唯一**。改批注时最稳的做法是：先读出现有最大 id，新批注从 `max+1` 开始，不要从 1 重排。

## 生成流程

1. **以返稿为底稿**，不要拿自己的旧稿重排——那样会丢掉老师的批注和已有修订。
2. **逐段字符级 diff**：把"老师原文段落"和"改写后段落"做最小编辑，只在真正变化的字符处包 `w:ins`/`w:del`。整段替换等于没走修订。
3. **批注锚点整段保留**：锚点挂在原段落上，回复作为新段落紧跟其后，或用 `w:ins` 追加在批注段内。
4. **写完立刻用 Word 打开验证**：不报错、批注列表完整、修订可见。

## 自检清单

| 检查项 | 通过标准 |
| --- | --- |
| 批注数量 | 与返稿一致，一条不少 |
| 批注 id | 正文引用与 `comments.xml` 一一对应 |
| 修订可见 | Word 里能看到所有 `w:ins`/`w:del` |
| 删除文字 | 全部在 `w:delText` 里 |
| 文本一致性 | 导出文本与预期逐字一致 |
| 引用编号 | 连续，无孤条 |
| 双引号字体 | 按 `format/本地格式规格.md` 核对 |
| 文件能打开 | Word/WPS 均无"文档损坏"提示 |

## 打包与发送

- 一个 zip，内含全部交付件；**文件名用 UTF-8**（`zipfile.ZIP_STORED` 会自动带 UTF-8 标记），否则 Windows 解压乱码。
- 超过邮箱容量用超大附件，不要拆成多个压缩包乱命名。
- 发送后截图存档，记录时间、收件人、附件清单。

## 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Word 提示"文档损坏" | 删除文字用了 `w:t`；或批注 id 不匹配 | 改 `w:delText`；重排 id |
| 修订看不到 | 只改了字体颜色 | 必须包 `w:ins` |
| 批注错位到别的段 | `commentRangeStart/End` 不对应 | 按段落重挂锚点 |
| 解压后文件名乱码 | zip 用了 GBK | 用带 UTF-8 标记的 zip |
| 老师说他改的地方被覆盖了 | 拿旧稿重排 | 以返稿为底稿重做 |
| 修改说明对不上正文 | 生成后又手改了 docx | 改稿走脚本，不要在 Word 里二次手改 |
