# 03 句式库（真实原句，按功能分类）

全部来自 41 篇语料，括号内是出处。**抄结构，不要抄内容**；同一句式在你的文章里换主语和对象。

---

## 1. 开篇：给场景，不给态度

- `近年来，大规模语言模型在自然语言处理领域取得了显著进展，并在工业机器人运维领域展现出重要的应用前景。`（梁鑫昊）
- `在如今数字化时代的背景下，电信行业面临着日益增长的客户服务需求，如何高效、准确地为客户提供服务、解决问题成为了关键的挑战。`（何一苇）
- `当前工程设计企业在知识应用层面普遍面临诸多问题，最为突出的就是知识难以形成复用。`（李粟）
- `为社会提供高效率的学习场所，是图书馆社会教育职能的体现。`（李艳茹，判断句开头）
- `知识对齐匹配旨在统一的特征空间中，找到不同知识图谱中指向同一现实世界对象的元素，是知识融合的核心环节。`（赵翔，定义式开头）

**规律**：首句只给钩子或承诺，从不自足。定义式开头后面必须跟分类；背景式开头后面必须跟一个可核验的数字。

## 2. 定义：中文（English，缩写）

- `检索增强生成（Retrieval-Augmented Generation，RAG）改变了查资料的方式。`
- `归一化折损累计增益（Normalized Discounted Cumulative Gain, NDCG）`
- `DB4LLM（Database for Large Language Model）技术应运而生，也称检索增强生成（Retrieval-Augmented Generation，RAG）。`（要鑫，"也称"给别名）

**规则**：首次出现给全称+缩写，之后只用缩写，**不要反复给全称**。

## 3. 指出现有不足（粒度决定水平）

**差**（只说结论）：
- `传统的数据治理方法已经难以适应多领域、复杂多元情境下的治理需求。`

**好**（说机制坐标）：`[承认对手在 X 成立] + [在 Y 条件下因 Z 机制失效]`

- `尽管 n-gram 模型在捕捉语言的局部结构和短距离依赖关系方面表现出一定的有效性，但它们在处理长距离依赖和复杂语义结构时具有一定难度。这是因为 n-gram 模型只能考虑有限的上下文信息。`（许宏新）
- `然而，这些方法往往只关注单个实体的局部最优匹配，忽略了知识图谱整体匹配的约束和影响。`（赵翔）
- `在零样本场景下，RAG 仍面临诸多挑战，尤其在密集检索阶段，系统通常仅依据原始问题进行语义匹配，难以识别隐含推理链与中间信息，导致相关文档检索不充分。`（宋婧）

**三个空槽都要填满**：在〔哪类输入/设置〕下，因为〔哪个机制〕，导致〔哪个功能〕失效。

## 4. 本文动作（作者出场，句子要短）

- `为此，本文设计了一种递归下降解析算法。`（郭利荣，17 字）
- `针对上述问题，本文提出了一种基于 LLMs 的企业端到端数据治理框架，覆盖数据整理、数据标准化、数据管理和分析的全流程。`（刘杰）
- `为了解决这些问题，本文设计并实现了一种基于主题分割与多阶段召回的检索增强系统。`（孙鸿博）
- `本文提出一种基于智能体的冲突消解框架（ACR）。`（要鑫）

**高频动词**（19 篇摘要统计）：实现 50、构建 46、设计 38、提出 37、研究 33、优化 20。
**第一高频搭配：设计并实现**（13 次）。标题带"设计与实现"的论文全都用了。

三条规矩：完成态优先（提出了/实现了，不用"将提出"）；"验证"只出现在效果句；序列词与动词配死（首先→设计/构建，其次→提出/引入，最后→实现/搭建）。

## 5. 举证：年份 + 人名 + 方法 + 作用

- `1956 年，Chomsky 等人提出了三种用于描述语言的模型，包括形式文法、优先状态自动机和递归函数，为后续语法分析等任务奠定了理论基础。`（许宏新）
- `詹丽华调查 11 个中文电子书平台的书目数据描述的规范性和关联性，提出规范我国中文电子图书书目数据。`（李艳茹，人名+动作+数量+结论）

**这是长句的主要产地**，因为塞了五个成分。不要为了"简洁"把它拆成三句——拆完就成了清单。

## 6. 结果：四件套

- `实验结果表明，主题分割算法在 Wikisection 和 Wiki-50 数据集上，与 CrossSegmentBERT 方法相比，边界误差分别下降了 3.4 个百分点和 1 个百分点。`（孙鸿博）
- `在 DL19 上的 recall@1000 达到 90.0%，TREC-COVID 的 recall@100 提升至 50.2，nDCG@10 达到 63.1，均显著优于现有无监督方法。`（宋婧）
- `本文提出的方法在实体抽取精确率（87.6%）和召回率（84.3%）上均显著优于纯 RAG 基线方法，关系抽取 F1 值提升至 81.5%，问答准确率达 90.8%，且知识更新延迟控制在 1d 以内。`（谢巨龙）

**位置规律**：数字放分句末作结论，或放括号内作限定；前面必须已经有"数据集/基线/指标"三者。

**最差句**（别学）：`在各项检索性能指标上均有显著提升。`（高宇德）

## 7. 结果归因（解释为什么涨）

- `1.2 秒，失败率为 0，原因是系统的本地预处理、缓存机制和硬件加速，缩短了响应时间。`（李致远）
- `MIRE 模型在 RAG 系统中的性能提升主要归功于其意图识别与关键槽位提权能力。`（何一苇）
- `QASPER 需要综合论文内部的信息，因此 RAPTOR 更高层的摘要节点能让它胜过……`（RAPTOR）

**格式**：`数字 + 归因`。连用两三次后换动词（原因是/主要因/这来自）。

## 8. 限定（防止过度推广）

- `在本次检索范围内，公开研究更多解决……`（综述边界）
- `仅凭借少数关键的归因头即可准确估计上下文片段的影响力分布。`（邓浩霖）
- `后者代表了 2025 年之前自动综述生成领域的最新方法（SOTA）。`（龚厚骅，给 SOTA 加时间戳）
- `本文重点研究最为广泛关注的情境-记忆知识冲突。`（要鑫，三类取一类）
- `由于大数据时代下实体数量井喷，当前知识对齐匹配主要集中在实体间的对齐。`（赵翔）

**限定词清单**：仅 / 只 / 限于 / 约 / 之一 / 在…条件下 / 在…范围内 / 某企业 / 最多 N 次 / 截至 X 年。

## 9. 收口（段落末句）

- `然而，这些方法整体上仍主要依赖符号层面的信息，在知识图谱更新频繁、表达多样化的开放环境中表现不佳。`（赵翔，转折收尾）
- `这表明 MIRE 模型召回的文本段更全面、准确，可以为 RAG 系统在信息检索方面带来一定的优势。`（何一苇）
- `设备改造、规程修订不断产生新知识；事故发生存在因果链条，需识别关键环节。`（谢巨龙，短句点题）
- `生技部门反馈系统快速定位事故原因链条，预防措施有效，分析时间由 2d 缩短至 4h。`（谢巨龙，效果收尾，无"综上所述"）

## 10. 转折与过渡

- `尽管如此，在零样本场景下，RAG 仍面临诸多挑战……`（宋婧）
- `尽管上一模块对文件进行了分类和保存，然而仍不足以支撑细致准确的知识搜索。因此，需要对文件内容进行进一步划分及编码……`（冀勇：让步→指缺口→为此，标准三拍）
- `该模块主要包含两个核心步骤：文件分割处理与向量化数据库构建。`（冀勇：编号+命名，先说有几个）

## 11. 本章小结

- `本章对商业银行领域知识图谱进行构建，利用大模型从银行内部和外部数据中抽取实体、属性和关系，结合提示工程和微调技术提高质量。通过构建同义实体库和 Jaccard 相关系数计算字符相似度，实现实体对齐和知识合并，确保知识库的准确性和一致性。最终，知识图谱存储在 Neo4j 图数据库中……为后续商业银行知识库系统提供精准高效的数据支持。`（许宏新）

## 12. 局限与展望

- `局限性：LLM 对专业术语有理解偏差，需人工校验；质量保障需安全专家介入关键审核；未验证核电、火电泛化能力。`（谢巨龙，冒号直陈，最伤的一条放最后）
- `我们的评估到目前为止集中在两个语料、各约 100 万 token。还需要更多工作来理解性能如何泛化到不同领域的其他用例。`（GraphRAG，承认外部效度）
- `后续仍需围绕权限约束、知识时效控制与复杂场景适配作进一步细化。`（刘泰成，写成下一步，不写"本文不足"）
- `未来，可进一步探索轻量化模型部署与多模态交互能力，以适配更复杂的应用场景。`（李致远，通用话，勉强及格）

## 13. 承认不利结果（高分技巧）

- `Empowerment comparisons showed mixed results.`（GraphRAG，直说没涨）→ 归因 → `Tuning element extraction prompts may help to retain more of these details.`（给可行动的修复方向）
- `部分指标已接近或超过轻量监督模型。`（宋婧，"部分""接近"是限定，不是谦虚）

## 14. 章节导航（代替"接下来我们来看"）

- `本章节围绕情境-记忆冲突场景，依次给出核心概念的形式化定义，包括……，为后续方法设计奠定理论基础。`（要鑫）
- `本章内容结构如下：从……的需求分析入手，……接下来……最后……`（何一苇）

## 附：不要用的句子

| 别写 | 因为 | 改成 |
| --- | --- | --- |
| 随着数字化浪潮的不断推进 | 没有宾语，且不可核验 | 引一个具体政策名/报告数据 |
| 该系统有效提升了 X 能力 | 无数字 | 给出指标、基线、数值 |
| 综上所述，本节完成了… | 元话语 | 直接给结论，或删 |
| 本课题不宣称首次提出… | 防御性声明，谁都知道不能宣称 | 删，直接写你做了什么 |
| 正文目标约 2.4 万字 | 写计划不写结果 | 删（这是开题报告的话） |
| 如图 1 所示，本系统架构清晰 | "清晰"是评价 | 写分层和各层职责 |
| 需要注意的是 / 值得一提的是 | 元话语 | 删 |
