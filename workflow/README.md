# 本地交付规格（workflow）

## 为什么还有这一层

`format/` 管"论文长什么样"，`workflow/` 管"什么时候交什么、交给谁、叫什么名字、用哪一版模板"。

这两层的共同点：**都是你所在学校/导师的事实，不是写作规律**。写死在公开 skill 里，别人装了就被带偏；学校改规定后也没人知道该改哪。

所以规则是同一套：

- 公开仓库只放**空模板**；
- 真实值由使用者注入到本地安装目录的这份文件里；
- Agent 每次涉及交付都要读它，**与 skill 正文冲突时以它为准**。

## Agent 的操作约定

1. 涉及交付（生成 docx、打包、发邮件、算截止期）时，先读 `workflow/本地交付规格.md`。
2. 若第 1 行是 `# 版本：未填写` → **不要猜**邮箱、命名规则、模板版本、日期，向使用者索取。
3. 拿到后逐项填入，标注来源与日期。
4. 只写进本地这份文件，**不要提交回公开仓库**。

## 隐私

这份文件会有邮箱、学号、姓名、导师信息。它**只在本机**，不进仓库、不进 git。仓库里的同名文件永远是空模板。

`git pull` 覆盖本地填写版时，先备份再合并——或者把填写版另存为 `本地交付规格_我的.md`，让仓库那份保持空壳。


## 模板与本地文件

- `本地交付规格.template.md` —— 公开模板，进仓库，**不要直接填它**。
- `本地交付规格.md` —— 你的本地文件，从模板复制而来，已在 `.gitignore` 里，不进仓库、`git pull` 不覆盖。

```bash
cp 本地交付规格.template.md 本地交付规格.md
```
